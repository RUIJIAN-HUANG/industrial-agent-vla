## 1.4 评委隐含加分项

主动展示失败并恢复：官方答疑明确，失败本身不必然扣分；关键是能感知失败并生成合理纠正序列。视频至少保留一次真实抓空或倾倒后的‘重新观察—纠正—成功’全过程。[2]

公开边界与负结果：若双VLA没有提升，给出严格消融并说明为何收敛为主备，比强行维持两个在线模型更可信。

防数据泄漏：展示运行时观测白名单和GT sidecar隔离测试，证明不是借仿真真值作弊。

可迁移性：增加一个未见零件或新格箱布局，只改配置/适配器，不改总Agent核心；用小实验支持‘框架可迁移’。

统计可信度：所有核心指标在冻结seed上连续运行，报告均值、分项失败和95%置信区间，不挑最好的一次。

工程成熟度：评委现场看到的是一次命令启动、状态可视化、故障有终止码，而不是多个终端手工拼接。


# 2. 最终架构定义：VLA负责认知执行，Agent负责闭环编排

下图作为冻结架构。本文只对其进行工程化定义，不把它改回传统“检测器给坐标—规划器给路径—控制器执行”的串联方案。


### 图1 工业智能体架构（轻量总Agent + VLA执行）

#### 1. 用户输入层

- **用户简单指令**：例如"把红色零件放进料箱"

#### 2. 调度控制层

- **总 Agent**（核心调度大脑）：
  - **功能**：任务类型识别、任务分配、状态管理、失败重试/切换。
  - **架构说明**：不单独设置独立的 NLP Agent，直接由总 Agent 统一处理。

#### 3. 动作执行层（并行的子 Agent 分支）

总 Agent 负责下发指令到对应的 VLA 模型：

- **OpenVLA 执行 Agent**（适合某类子任务）：理解简单指令 + 结合视觉执行。
- **π0.5 执行 Agent**（适合某类子任务）：理解简单指令 + 动作生成。

#### 4. 物理/仿真执行层

- **机械臂 / 仿真环境执行**：接收执行 Agent 的指令并驱动物理或仿真实体运行。

#### 5. 环境感知与反馈闭环

- **环境反馈 / 感知验证**：利用 YOLO / 状态检测 / 执行结果判断，抓取环境最新状态。
- **总 Agent 更新状态并决定**：根据反馈决定"继续"、"重试"还是"切换 Agent"，并将控制流重新反馈给顶层的总 Agent，形成完整的运行闭环。

#### 6. 架构核心思想

- **核心思想**：VLA 负责简单自然语言的视觉落地和动作生成；总 Agent 负责任务调度与闭环管理。


## 2.1 三层边界


| **层** | **允许做什么** | **明确禁止** | **为何不违背****VLA****路线** |

| **expected_postconditions** | in_cell && upright && stable_0.5s | 核验器比较的声明式条件。 |
| **executor/status** | pi05 / VERIFYING | 记录路由和状态，不改变图像语义。 |
| **retry_count/failure_code** | 1 / TILTED_AFTER_PLACE | 驱动同模重规划或一次切换，防止死循环。 |


## 2.4 总Agent状态机


| IDLE → VALIDATE_COMMAND → ROUTE_POLICY → OBSERVE → EXECUTING
                                                ↑            ↓
                                      REPLAN_SAME_POLICY ← VERIFY
                                                │            ├─ postcondition=true → DONE
                                                │            ├─ failure,retry=0 → REPLAN
                                                └─ retry=1 → SAFE_STOP → SWITCH_POLICY → OBSERVE
                                                             ├─ system/safety fault → ABORT
                                                             └─ retry exhausted → ABORT_WITH_REASON |
| --- |


每个episode最多切换一次；切换后不再切回，避免两个Agent乒乓振荡。

切换只能发生在机械臂停止、旧动作队列清空、重新获取图像之后；不得拼接两个模型的剩余动作块。

NaN、Inf、关节越界、模型服务超时、相机失联属于系统故障，直接安全停止，不用换模型掩盖。

语义失败先让同一VLA基于最新图像重规划一次；第二次仍失败才考虑切换。

若核验置信度低，不得直接宣布失败；再取2—3帧稳定图像做多数投票，仍不确定则安全终止并记录UNCERTAIN。


## 2.5 为什么双VLA必须用实验决定，而不是用直觉路由

“OpenVLA适合简单、π0.5适合复杂”只能作为预注册假设。两个模型的训练域、输入预处理、动作块和归一化均不同；最终路由表必须由冻结验证集生成：对每个任务族选择成功率最高、延迟和安全指标达标的模型。若π0.5或OpenVLA-OFT全面占优，则另一个模型应退为对照或备份。


| **任务族** | **可观测文本****/****任务特征** | **初始候选（待验证）** | **最终决策依据** |
| --- | --- | --- | --- |
| **单物体直接取放** | 单目标、单容器、无姿态修正、短时序 | OpenVLA-OFT | 50-seed成功率、平均动作步、P95延迟 |
| **属性视觉落地** | 颜色/形状/材质区分，遮挡或高反光 | 两者均测 | 困难子集成功率与错误目标率 |
| **指定格****+****姿态** | 行列约束、立放、可能二次调整 | π0.5优先 | 正确格率、立放率、恢复率 |
| **多物体****/****长时序** | 重复整理、最多区域、料箱装满/移动 | π0.5优先 | 整任务成功率、长时序漂移、超时 |
| **非操作****/****设置命令** | 询问状态、修改阈值、无机械臂动作 | 轻量NLP分支 | 意图准确率、拒绝错误动作 |
| **未知或歧义** | 对象/位置缺失，任务族外 | 请求澄清/拒绝 | 误执行率必须为0 |


# 3. 各组件极详细设计


## 3.1 轻量总Agent

推荐实现为一个显式状态图，而不是让大语言模型自由循环。可使用LangGraph承载State/Node/Edge和本地持久化，也可用纯Python FSM；二者选一。关键是状态、分支和终止条件可测试，不是框架名称。[12]


| **节点** | **输入** | **处理** | **输出****/****异常** |
| --- | --- | --- | --- |
| **validate_command** | 原始文本 | 长度/敏感词/必要槽位检查；本地同义词规范；Pydantic校验 | 合法TaskSchema；歧义则CLARIFY，不启动机械臂 |
| **route_policy** | task_family、服务健康、冻结路由表 | 查询验证集生成的静态映射；记录route_reason | executor_id；服务不可用则降级或ABORT |
| **observe** | 相机、本体状态 | 时间戳同步、黑帧和shape检查；原图传给适配器 | ObsPacket；相机异常则安全停止 |
| **execute** | 模型动作块 | NaN/范围/坐标/过期检查，执行前K步；看门狗 | ExecutionResult；超限不下发 |
| **verify** | 执行后新RGB、预期条件 | 调用YOLO核验器；多帧投票；不读取GT | PASS/FAIL/UNCERTAIN + failure_code |
| **reflect** | 历史、failure_code、retry_count | 生成简短失败上下文并保留完整原指令；决定同模重规划/切换/终止 | next_state与可审计reason |
| **persist** | 全状态 | SQLite/JSONL写入；图像路径、模型SHA、配置、延迟 | 可重放episode；写失败不影响急停 |


### 3.1.1 指令理解最小实现

P0：模板/词典 + 结构化校验。覆盖颜色、对象、数量、容器、行列、姿态、顺序词和否定词；对无法唯一落地的指令必须澄清。

P1：本地小型指令LLM只把口语转为TaskSchema，温度0、JSON Schema约束；输出仍由确定性校验器验证。已有大模型/prompt按官方文件允许使用。[1]

P2：不做独立NLP微调。40天里，语言分支的价值在鲁棒解析与拒错，不在再造一个对话模型。

禁止：解析器把任务改写为‘移动到坐标(x,y,z)’或手写‘接近—闭爪—抬起’序列；那会重新变成模块化动作规划。


### 3.1.2 记忆、重试与反思


| **记忆层** | **保存内容** | **生命周期** | **用途** |
| --- | --- | --- | --- |
| **请求记忆** | 原指令、TaskSchema、路由理由 | 单episode | 防止重试时语义漂移 |
| **动作记忆** | 每个动作块、执行前后图像、耗时 | 单episode+归档 | 复盘动作跳变、切换是否安全 |
| **结果记忆** | 核验状态、failure_code、置信度 | 单episode+统计 | 同模重规划、失败簇分析 |
| **实验记忆** | commit、checkpoint、config、seed、硬件 | 永久 | 指标可复现，禁止口头‘这次更好’ |


反思不是让LLM写长篇自言自语，而是生成结构化`Reflection{observed, expected, mismatch, next_decision}`。例如：`observed=TILTED_IN_TARGET_CELL; expected=UPRIGHT; next_decision=REPLAN_SAME_POLICY; context='零件已入二行三列但倾倒，请基于新图像调整为直立'`。

### 3.2.2 OpenVLA-OFT微调执行清单

先在官方LIBERO检查点复现推理，连续100次记录输出shape、显存、P50/P95延迟和内存增长；没有官方复现不得改代码。

用脚本教师轨迹做动作回放，确认坐标、夹爪符号和归一化；任一维不一致时先修数据，禁止靠训练‘学会纠错’。

从canonical数据按episode导出OFT/RLDS；过滤真正无意义的近零动作，但保留夹爪闭合、接触稳定等有意义等待。

先用20—50条做过拟合烟测：模型应能复现训练场景。若训练loss下降但闭环不动，优先排查图像裁剪、action stats和控制频率。

主训练使用约100—500条/核心技能的高质量轨迹；每个checkpoint都在独立验证seed闭环评测，不能只看离线L1 loss。

最终只选验证集最优checkpoint；测试集只跑一次正式评测，防止用测试集调参。

### 3.3.1 π0.5适配流程

复现`pi05_libero`或最接近的官方checkpoint，保存仓库SHA、模型SHA和官方样例输出。

定义本项目DataConfig：前视图、腕部图、本体状态、prompt、7维动作；对不足的模型最大维度由适配器padding，输出只取实际7维。

生成LeRobot数据集并运行norm stats；检查每维分布、1%/99%分位和夹爪双峰，发现异常先回到数据QA。

用JAX LoRA做小数据过拟合，再训练主数据；训练与推理服务完全分环境，不覆盖OpenVLA的transformers依赖。

模型返回动作块后，适配器反归一化、裁维、加`space_id/frame/control_hz/checkpoint_sha`，总Agent执行前K步后重新观察。

失败切换时清空openpi客户端缓存和动作队列，重新传当前图像；不得沿用OpenVLA的归一化统计。

### 3.5.1 核验器与仿真GT的严格边界

训练标注：Replicator/仿真GT自动产生bbox、mask、pose和格口真值；允许用于训练YOLO。

在线核验：只读取渲染RGB和允许的机器人传感器状态，输出类别/框/掩码/置信度；不得读取object pose、semantic_id、contact truth或success flag。

离线评测：GT sidecar与核验器预测在独立进程比较，计算mAP、F1和后置条件准确率。

Agent触发：核验器只给`postcondition`和`failure_code`，不提供目标像素坐标、抓取点或世界坐标给VLA。

必须做消融：无核验/固定回合终止 vs 有核验闭环，证明Critic提高恢复而非替代Actor。


## 3.6 机械臂执行与安全层

## 4.7 物理与控制基线

单位统一为米/千克/秒；所有USD资产入库时自动检查包围盒尺寸，圆柱直径/高度与规格表差异>2%则拒绝。

动态零件碰撞体使用box/capsule/convex hull；复杂mesh只作visual。重叠collider、非合理惯量和尺度错误是弹飞/爆炸首因。

reset先拒绝采样避免相交，再静置0.3—0.5s；保存seed和全部scene_params，重置失败独立计数。

摩擦初始范围0.4—0.9、质量±20%、恢复系数0—0.1；禁止把摩擦调到不真实的极端来掩盖抓取问题。

脚本教师先通过差分IK完成到达—夹取—抬升—对格—释放；脚本都不稳定时禁止归咎VLA。

GUI只调试，训练/正式评测统一使用同一headless配置；每晚固定seed回归，防止GUI/headless结果漂移。

# 5. 数据系统：一份canonical轨迹，两条模型数据支线

仿真环境不得直接依赖OpenVLA或openpi的数据格式。先建立可回放的canonical episode，再由两个纯转换器导出各自格式。这样动作合同、split和成功标签只有一个事实源，避免两名模型负责人各造一套数据。


## 5.1 Canonical Episode Schema


| episode/
  meta.json              # episode_id, seed, task_id, instruction, scene_params, schema_version
  steps.parquet|hdf5     # timestamp, robot_state[d], action[7], done, failure_code
  front_rgb/000000.jpg   # 同一step的前视图
  wrist_rgb/000000.jpg   # 可选
  gt_sidecar.npz         # pose/bbox/mask/contact/target_cell；ONLINE进程无读取权限
  result.json            # success, completion_reason, retries, executor, latencies
  sha256.txt             # 完整性 |
| --- |


| **字段组** | **强制校验** | **常见静默错误** |
| --- | --- | --- |
| **图像** | uint8、HWC、RGB、时间戳单调、黑帧率0、相机内外参可追溯 | BGR当RGB、上下翻转、训练/推理crop不同、RGB/深度错帧 |
| **状态** | 维度/顺序/schema_version一致、无NaN、单位明确 | 关节角与末端位姿混用、四元数wxyz/xyzw混淆 |
| **动作** | 7维、频率、frame、axis-angle、夹爪语义、范围 | 两模型归一化混用、符号相反、回放速度不同 |
| **语言** | 原指令与task target一致、编码UTF-8、同义改写不改语义 | 把结构化槽位替代完整指令、颜色标签冲突 |
| **标签** | 成功几何判定可复算、failure_code单一主因+次因列表 | 把reset失败算策略失败、用YOLO预测当GT |
| **划分** | 按episode/scene seed/资产组合；manifest只读有哈希 | 相邻帧随机切分导致严重泄漏 |

## 5.3 数据配比与采集优先级


| **数据类型** | **占比建议** | **作用** | **采集规则** |
| --- | --- | --- | --- |
| **标准成功** | 约70% | 学习短、稳定的主路径 | 覆盖目标位置/姿态/颜色/格位；去长停顿 |
| **扰动后成功恢复** | 约20% | 学习重新抓取、调整姿态、再次放置 | 从抓空/偏抓/滑落/箱口碰撞等安全状态继续 |

# 6. 模型训练与调优计划


## 6.1 训练优先级


| **优先级** | **对象** | **为什么** | **何时停止** |
| --- | --- | --- | --- |
| **P0-1** | YOLO11s-seg核验器 | 最快形成mAP证据和闭环failure code；不依赖VLA先成功 | mAP/后置条件F1达门且错误可接受 |
| **P0-2** | 一个主VLA | 先证明VLA可在本域闭环；按官方复现成功与硬件选择OFT或π0.5 | ID成功≥60%且无系统性动作错误 |
| **P1** | 第二VLA | 验证互补和路由创新 | D24若无≥5—8个百分点增益即降级 |
| **P2** | 量化/蒸馏 | 只有部署确实受显存/延迟限制时才有价值 | 任何成功率损失>3个百分点或影响复现即取消 |


## 6.2 YOLO训练

用Replicator生成框/实例mask/状态标签；先人工检查每类100张，尤其反光边缘、遮挡实例和格口polygon。

按scene seed切train/val/test，不按图像帧；确保同一episode的连续帧只在一个集合。

先YOLO11s-seg固定官方预训练权重和版本；输入尺寸、batch由显存一次性选择，训练早停依据val mAP50-95。

分别报告普通、密集、遮挡、强反光、姿态状态五个子集；不能用混合平均掩盖最难工业条件。

后置条件阈值只在val选择；test输出mAP50、mAP50-95、Precision、Recall、每类AP、F1、P50/P95延迟和显存。

做仿真GT vs YOLO核验的差异表；Agent在线只能用后者。


| **Gate** | **最低线** | **冲奖线** | **不达标动作** |
| --- | --- | --- | --- |
| **检测****/****分割** | mAP50≥0.85 | mAP50≥0.92；mAP50-95≥0.65 | 补困难样本、检查标签；不先换更大模型 |
| **状态判别** | 宏F1≥0.80 | ≥0.90 | 统一upright/fallen定义；增加姿态边界样本 |
| **后置条件** | PASS/FAIL宏F1≥0.85 | ≥0.92 | 多帧投票、格口polygon校准 |
| **速度** | 满足VLA闭环；P95<100ms为底线 | P95<50ms（目标硬件） | 缩图/导出ONNX或TensorRT，仅在精度可接受时 |


## 6.3 主VLA训练流程


| **阶段** | **数据****/****训练** | **闭环验收** | **失败时先查** |
| --- | --- | --- | --- |
| **官方复现** | 官方LIBERO checkpoint，不改代码 | 100次推理无崩溃；官方样例可跑 | 依赖、权重、图像键、GPU |
| **接口烟测** | 20—50条本域演示，刻意过拟合 | 训练场景能复现动作；回放≥95% | 坐标、频率、夹爪、norm stats、裁剪 |
| **首轮微调** | 100—500条/核心技能；LoRA；1—2组超参 | ID val成功≥60% | 演示质量、初始分布、动作块K_exec |
| **定向回灌** | 只补前三大失败簇 | 每类失败显著下降，整体不回退 | 标签/分布漂移、过拟合 |
| **冻结** | 选择val最优，不选最后一步 | 固定50-seed回归，无P0 | checkpoint选择规则、缓存和服务版本 |


## 6.4 双VLA训练的公平性协议

同一canonical episode清单、同一train/val/test场景、同一自然语言和同一物理动作语义；允许各模型使用自身官方预处理与归一化。

总训练资源需记录GPU小时；如果一模型获得更多数据/调参次数，报告必须披露，避免不公平结论。

模型服务分别预热后测延迟；冷启动、显存、崩溃和超时也是路由成本，不能只比成功率。

每个模型至少3个训练seed或在资源不足时做1个训练seed+多评测seed，并明确局限；核心测试每任务50回合。

D24前预注册保留双模型硬条件：宏平均成功率较最佳单模提升≥5个百分点（理想≥8），复杂任务子集≥10，切换超时失败<5%，路由错误<10%。


## 6.5 为什么40天不把蒸馏和量化放主线

知识蒸馏和量化有研究价值，但它们不直接修复动作合同、演示质量或闭环失败。只有D33后候选模型已稳定、且部署因显存/延迟无法达标时，才做一项受控压缩实验；报告压缩率、延迟/显存与成功率折损。[17][18]


| **条件** | **允许动作** | **禁止** |
| --- | --- | --- |
| **成功率达标但推理显存不足** | 优先官方低精度/量化加载，固定20—50 seed回归 | 边量化边改动作空间/数据 |
| **模型服务能运行但延迟偏高** | 缓存、预热、缩短执行prefix、服务器独占；再尝试量化 | 用论文硬件数字代替本机实测 |
| **模型尚不能稳定完成任务** | 回到数据、接口和微调 | 蒸馏一个失败的teacher |
| **D35****以后** | 只修P0阻断 | 新增蒸馏、换模型、换平台 |

`expires_after_ms`：超过时限的动作块丢弃并重新观察。

## 8.3 正式评测协议

冻结`eval_protocol.yaml`：任务族、每类回合数、seed、场景分布、超时、最大重试、成功判定、模型/配置SHA。

开发期每类20—30回合；D35最终每个核心任务至少50个未见seed，总回合建议300—500。

每个回合从自然语言开始，自动reset、运行、核验、记录；除安全急停外禁止人工接管。

报告成功率的Wilson 95%置信区间；同一seed做配对比较时保留逐回合结果，可用bootstrap估计差异区间。

同时报告全部失败码和视频索引；不得删除异常值，系统崩溃计为失败并单列。

路由表/阈值只使用val；测试集结果出来后不得再改路由并重新宣称正式结果。

## 11.1 十条高频雷区

先训练大模型再做仿真：最后发现动作坐标/相机错，所有训练作废。正确顺序是脚本教师→回放→数据→小样本过拟合→闭环。

把最新版本当最稳版本：40天项目必须固定成熟配对，不做框架beta测试者。

两个模型共用同一归一化统计：公共的是物理动作语义，不是normalized tensor。

把YOLO框给VLA‘提高成功率’：这会改变核心技术主张并有GT/模块化作弊嫌疑。

按帧随机切分数据：连续帧几乎相同，会制造虚高验证结果。

只看训练loss：机器人闭环分布偏移很强，必须每个checkpoint跑独立验证场景。

为了工业感做过度美术：首周先用规范几何体和合理材质，把时间留给物理、数据和闭环。

无限重试显得智能：评委更在意安全、可解释终止和失败分类。

D35还在换模型/量化/加多臂：材料、复现、统计会全线崩溃。

视频只剪成功：官方强调失败感知与恢复，保留一镜到底和原始失败更有说服力。

| def run_episode(raw_instruction):
    task = validate_and_parse(raw_instruction)      # 只解析任务元信息
    executor = route_table[task.task_family]        # 验证集冻结映射
    state = new_state(task, executor)

    while not state.terminal:
        obs = simulator.observe_online_whitelist()  # RGB + proprio；无GT
        chunk = executors[executor].infer(obs, raw_instruction)
        safe_chunk = validate_and_clip(chunk, ACTION_CONTRACT)
        simulator.execute(safe_chunk[:K_EXEC])

        new_rgb = simulator.capture_rgb()
        verdict = verifier.check(new_rgb, task.expected_postconditions)
        persist(state, obs, safe_chunk, verdict)

        if verdict.pass_:
            return DONE
        if verdict.uncertain:
            verdict = verifier.vote(simulator.capture_rgb_burst(3))
        if is_system_or_safety_fault(verdict):
            return safe_abort(verdict)
        if state.retry_count == 0:
            state = replan_same_policy(state, verdict)
        elif state.switch_count == 0 and alternate_is_allowed(task):
            simulator.safe_stop(); executors[executor].cancel_pending_chunk()
            executor = alternate(executor); state = switch_once(state, executor, verdict)
        else:
            return abort_max_retry(verdict) |
