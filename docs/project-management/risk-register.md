## 2. P0 升级规则

出现以下任一情况立即通知 A 和 F，并在两小时内创建 Issue：

- 官方基线哈希变化或需求解释冲突；
- 安全越界、仿真 GT 泄漏、密钥/许可问题；
- Gate 当天无法满足最低证据；
- 关键依赖/模型/平台不可获取；
- 主分支、提交包或评测原始数据被污染；
- 预计影响关键路径超过一天。

A 必须在当天给出一种记录在案的决定：

1. 修复并保留范围；
2. 启用预先定义的回退方案；
3. 删除低价值范围；
4. 接受风险并写明截止时间、owner 和退出条件。

“继续观察”不能单独作为 P0 决策。
